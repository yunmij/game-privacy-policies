## 目录约定

- 首页 `index.html` 列出已发布政策的游戏。
- 每款游戏一个目录：`<game-slug>/index.html` 列出该游戏的平台。
- 每个平台独立政策：`<game-slug>/<platform>/index.html`。
- 平台审核表单填写对应平台的完整政策链接，不填目录首页。
- 不同平台按实际能力和信息处理填写，不默认共用同一份声明。

## 新增或更新

1. 核对该游戏对应平台的开发者主体、实际信息类型、用途、权限、平台服务、保存与删除方式、未成年人说明、联系邮箱。
2. 在游戏和平台目录创建或更新 `index.html`，标注更新与生效日期；页面无需登录，不依赖外部脚本、字体或统计服务。
3. 新增游戏或平台时更新对应目录页和本表。已提交平台的链接保持稳定，后续更新内容直接修改原文件。
4. 提交并推送到 `main`，GitHub Pages 从仓库根目录自动发布。
5. 等待 Pages 构建通过，打开公开链接核对正文，再更新对应平台后台；内容有实质变化时同步更新游戏内告知与授权。

## 托管设置

GitHub Pages：Deploy from a branch → `main` → `/ (root)`；启用 HTTPS。`.nojekyll` 表示直接发布静态文件。

访问网页时，GitHub Pages 会出于安全目的记录访问 IP，见 [GitHub Pages 说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages#data-collection)和 [GitHub 隐私声明](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement)。

该仓库不存放游戏源码、玩家数据、身份证明、私人电话、访问凭据或平台日志。其他游戏只有在对应政策完成核对后才加入目录。
